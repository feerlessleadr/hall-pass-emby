Companion phone UI: the Library > Hall Pass tab in Embidextrous (`C:\dev\embidextrous`, `docs/HANDOFF.md` there). Tag Team (the general bulk tag editor, `C:\dev\tag-team-emby`) is **not built**.

## 2. Pipeline: how a track becomes a decision
1. **Scan** (`ScanJob`, manual / nightly `ScanTask` 3:30 / `AutoScan` of new tracks after 30 s of quiet): `TrackAnalyzer.AnalyzeAsync` per audio item. A track is skipped when its file key (path, size, time, lyric streams, sidecar stamp) and the *evidence version* (hash of word list, edits, scanner options, skipped genres, stage switches, a hand-bumped stage token) are unchanged. Bump the stage token in `HallPassState.EvidenceVersionFor` whenever the evidence logic changes so every track is looked at again (now `stages-v4-per-source-lyrics-and-ambiguous-words`).
2. **Evidence** (`Evidence.cs`: source, verdict Explicit/Clean/None, confidence, detail):
   - **lyrics**: every readable lyric source is scanned separately (`LyricsEvidence.Combine`): the lyrics embedded in the audio file (Emby lists them as a `text` Subtitle stream titled "Lyrics") and an external `.lrc` (Emby lists it as `lrc`). Sources giving the same answer merge into one line "from A and B: ..."; an explicit one plus a clean one stay separate, which the decision engine turns into **Conflict -> Review**. If Emby lists no readable lyrics, `SidecarLyrics` looks for `<track name>.lrc|.txt` in the folder (any case, 512 KB cap). If there are none, a `None` evidence line says what was looked for ("no lyrics found: ...") so a no-evidence track can be explained.
   - **title**: `TitleHeuristics.TitleProfanity` (severe word 0.85, moderate 0.55, mild/clean nothing) plus the old markers ("(Explicit)", "(Clean)", "(Radio Edit)", nsfw/sfw in title, album or three folder names; 0.6/0.6/0.4).
   - **file tags** (`FileTagReader` via Emby's ffprobe, 30 s): advisory flags (`EmbeddedTags`), ISRC, album barcode.
   - **online** (opt-in): Deezer by ISRC else artist+title, iTunes by album barcode (`OnlineStage`, rate limited 8/s and 20/min, cached 90 days, negatives 14); online "clean" is capped at 0.85. **LRCLIB** (`LyricsStage`, only when online and the LRCLIB box are on and the track has no local lyrics): length must be within 5 s, evidence capped at 0.7 (alone: likely clean or review, never certain).
3. **Decision** (`DecisionEngine.Decide`, thresholds in `DecisionSettings` with presets Balanced/Conservative/Relaxed): manual override wins; skipped genre -> Skipped; no explicit and no clean evidence -> Review/NoEvidence; explicit >= 0.75 -> Explicit unless clean evidence disagrees and explicit < ConflictExplicitWins (0.9) -> Review/Conflict; clean >= 0.9 -> Clean; two different clean sources >= 0.8 -> Clean (CorroboratedClean); clean >= 0.5 (LikelyClean setting) -> Likely clean; else Review (WeakClean / Suspected / Conflict).
4. **Lyrics scoring** (`ProfanityScanner`, pure): whole words only, inflections (`s es ed ing in y ie ies`), leet and masked spellings (`f*ck`, `sh!t`, `fuuuck`), stems `fuck` and `shit` inside compounds, allowlist (Scunthorpe etc.). Tiers: severe 3, moderate 2, mild 0 (recorded, scores nothing). Score >= 3 explicit (0.75), >= 10 strong (0.95), >= 1 suspect (0.5), clean needs >= 15 words (0.5).
   **Dual-meaning rules (1.3.0.0, in `default-wordlist.json`)**: `exactOnly` (cock, dick: no suffix/stem matches, so "cocked" is not "cock"), `nameLike` (dick: written with a capital in the middle of a line, line not mostly capitals => term "dick (a name)", weight 0), `ambiguous` (dick, cock, cocks: one use counts 1 = suspect, two or more count in full). Owner's tiers (kept): mild damn/hell/crap/arse/pissed; moderate ass/piss/...; severe shit/bitch/dick/cock/pussy/whore/slut/tits/titty/blowjob/porn and the f, c, n words.
5. **Writing** (`WriteJob`, only when `DryRun` is off, started by Apply, or after a scan if `ApplyAfterScan`): exactly one of the four managed tags per decided track (`TagPlan`), other tags untouched, the track's `Tags` field locked (so a "replace all metadata" refresh keeps it), every change journalled (`JournalStore`, job files) and undoable from History; a track edited since is left alone unless "Also restore tracks that were edited since". Optional roll-up (`RollUp`, off): albums (`Audio.AlbumId`) and artists (`Audio.ArtistItems`) get `explicit` when any track is explicit and lose it when none is (a partial scope such as new tracks only ever adds). Album/artist items are Emby virtual items; this was verified live.

## 3. Settings (`PluginConfiguration`, saved as `HallPass.xml`) and data files
Preset, LikelyCleanConfidence, MinWordsForClean, PerTermCap, SkipGenres (default Classical, Instrumental, Soundtrack, Score); ExtraSevere/Moderate/MildWords, IgnoredWords, ExtraAllowedWords; tag names (explicit, clean, likely-clean, explicit-review); DryRun (**default true**), TagSkippedAsClean, RunMetadataSavers, BatchSize 200 / BatchDelayMs 50; AutoScanNewTracks (on), ApplyAfterScan (off); ReadFileTags (on); OnlineEnabled (off), OnlineDeezer, OnlineITunes, OnlineLyrics (off), cache days; RollUpAlbums, RollUpArtists (off); journal keep 25 jobs / 30 days. Data files in `plugins/configurations`: `HallPass.Evidence.json` (decisions and evidence, never lyrics), `HallPass.OnlineCache.json`, the journal. `Validate` in `Plugin.cs` refuses bad values (400).

## 4. HTTP API (`/emby/HallPass/...`, admin only, `Authenticated(Roles = "Admin")`; API version 1)
`GET Info`, `GET Status` (job, write job, auto-scan, stats ByDecision/ByReason/Overrides, DryRun), `POST Scan {Force}`, `POST Scan/Cancel`, `GET Review` (Decision, Reason, Text, Source, Overrides, Artist, Album, NoAlbum, Sort = `confidence`|`plays`, Skip, Take; rows carry Plays), `GET Review/Albums`, `GET Review/Artists`, `GET Items/{Id}`, `POST Items/Decide` (ItemIds, or `AllMatching` with `Match...` filters, cap 20,000; returns Changed/Matched/Truncated), `POST Items/Rescan {ItemId}`, `POST Lookup` (describe a track; asks Deezer/iTunes/LRCLIB on demand), `GET WordList`, `POST WordList/Test`, `GET Apply/Preview`, `POST Apply {Confirm, ConfirmLarge}`, `POST Write/Cancel`, `GET Jobs`, `POST Jobs/{JobId}/Undo {Force}`. Route classes live in `Services/HallPassApiService.cs` and `Services/ToolsApiService.cs`. `PlayCounts` sums Emby's per-user play counts (cached 60 s).

## 5. The plugin web page (`HallPass.HallPassConfiguration.html` + `.js`, embedded resources, controller `HallPassConfigurationjs`)
Five top tabs (Dashboard with a "How to use" card and "You are here" line, Review, History, Try it, Settings). Review: filters, Albums/Artists/Tracks, sort, "Only tracks I decided myself" (ticking it sets Decision to All), select all on page or all N matching, per-row Rescan. Settings: five section buttons inside one form (Scoring, Word list, Lookups, Tags & writing, Keeping up to date), one Save. Styling rules that cost time: define our own `.hp-card` (Emby's `paper-card` has no visible style); `is="emby-textarea"` does **not** draw a `label` attribute (write a `<label class="hp-label">`); Emby lays `.checkboxContainer` out as a row (override to block so the explanation sits underneath); Emby caps `form` at ~54em (override); narrow windows stack the Albums/Artists/History tables (media query at 900px). Copy style the owner wants: full plain sentences, American spelling ("recorded", not "journalled"), no sentences that end in "is"/"are", say where a setting lives (Settings > Tags & writing > Dry run).

## 6. Decisions and their reasons (chronological highlights)
- Names: Hall Pass and Tag Team (Clean Cut, Bleep, Swear Jar checked and dropped). GUID `6ca80343-2b60-40de-ab81-7a41628fcaf2` never changes.
- Likely-clean is its own tag (owner's choice) so playlists can allow only `clean` or also `likely-clean`. A SmartLists `NotContains explicit` is a substring match and therefore also excludes `explicit-review` (verified live); `Equal explicit` is the exact tag.
- Dry run on by default; the owner turns it off. Scanning and marking are safe with dry run on; turning it off needs no rescan; unresolved review tracks get `explicit-review` on Apply; a later Apply writes only differences.
- Online lookups, LRCLIB, roll-up are opt-in and off by default (they send data out or write more tags). Lyrics are never stored.
- Manual decisions are never replaced by a scan. "Clear my decision" returns to the evidence.
- Conflicts go to a person rather than a quiet winner (1.3.0.0), because lyric transcriptions often differ (the embedded text and the .lrc are separate transcriptions).
- Settings that change evidence require "Rescan everything"; the evidence version makes "Scan now" redo everything automatically after an update that changes logic.

## 7. Lessons and gotchas
- **Plugin page cache:** Emby serves the page with an ETag from the *plugin version*; rebuild under the same version and a browser (or the app's browser pane tab) can keep showing the old page. Bump the version for every page change; after updating a plugin tell people to hard refresh (Ctrl+F5). In the Claude browser pane, open a **fresh tab** to see a new page (an old tab stacks stale views; there is a tab cap, close old ones).
- **Test the page with the browser's own validation**, not only by script: 1.0.0 shipped with a number input (`min=1 step=10`) that made the default 200 invalid and blocked Save.
- **Look at the real thing before trusting a fix**: the 1.3.0.0 investigation printed each matching word from the owner's real files (embedded vs .lrc) with a scratch harness (a console project compiling `Core/**/*.cs` plus the embedded word-list resource and calling the private `Match` by reflection). Never print lyrics; print the matched token, term and position only. Embedded lyrics are the `lyrics-XXX` tag (ffprobe `format_tags`).
- Owner's real library facts: every track has two lyric sources (embedded + `.lrc`), duplicate album folders exist ("(1)" files), 517 tracks needed review in the first dry run (mostly no evidence before online lookups and the lyric-file fix).
- Shell/tool traps: see the memory note "tooling-pitfalls" (here-docs and perl with braces fail to parse in the Bash tool: write scripts with the Write tool; sed `&` in a replacement inserts the match; Edit needs a prior Read).

## 8. Not verified / known gaps
Linux or Docker servers (paths, ffprobe, permissions); libraries over a few hundred tracks; other Emby versions; NFO savers on; Emby stopping mid-write; the lyric-file fallback inside a full scan on the owner's server (no way to confirm why their `.lrc` files were not read before 1.2.0.0; the "no lyrics found" evidence line will say); phone widths below 600 px for the plugin page; a lowercase "dick" used as a name, a name at the start of a line, and other everyday senses (ass, pussy, tits) still score; the app's swipe gesture on a real phone.
